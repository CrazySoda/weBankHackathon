# DECISIONS

Per BUILD_PLAN §9: decisions made when a requirement was unclear, each with the
choice and why. Team can veto; changes must update the code + tests.

| # | Decision | Why |
|---|----------|-----|
| 1 | Backend talks to LiteLLM proxy with the **OpenAI-compatible `AsyncOpenAI` client**, not the `litellm` python SDK | Rule 0.8 says no direct provider SDK calls; the proxy owns provider keys + fallbacks. `openai` client pointed at the proxy is the standard client for an OpenAI-compatible gateway and keeps one HTTP path. |
| 2 | LiteLLM image pinned to **v1.105.0** (`ghcr.io/berriai/litellm@sha256:60947…`) | Plan §0.11 flags 1.82.7/1.82.8 as malicious; 1.105.0 is the current release at build time (PyPI `litellm` 1.105.0). Digest resolved live from ghcr. |
| 3 | Postgres image = **`pgvector/pgvector:pg18`** (not `postgres:18`) | pgvector extension is required by the stack table; this image ships it on PG18. |
| 4 | Langfuse runs under a **compose profile `obs`** (`--profile obs`) | Langfuse v3 drags in ClickHouse/MinIO; demo stack stays lean unless observability is wanted. LiteLLM callbacks degrade gracefully without it. |
| 5 | `DealState` gains one operational field `fatal_error: str \| None` (not in plan §3.1 list) | Rule 0.6 (fail closed → escalate) needs an in-state signal routers can read, because a raised exception cannot route a conditional edge in LangGraph. Set only by hooks, checked first by every router. |
| 6 | Budget `max_steps` counts **node executions**; check is `steps >= max_steps` before each node | Makes `recursion_limit = step budget` natural; off-by-one verified by test. |
| 7 | Money comparisons/coercions use pydantic **`strict=True`** (no str/bool→int coercion) | Money is integers only (rule 0.9); silent coercion is a float-adjacent footgun. |
| 8 | Waived/fixed findings **survive check re-runs** (`merge_by_check_id`) | A human waiver must not be silently erased by a re-run; re-detection keeps the waiver (M6 policy still requires the named human + reason). |
| 9 | Zero-amount FX conversion with a positive fixed fee **raises** | A fee on nothing is a caller bug, not a −fee result. |
| 10 | DB/Redis integration tests are **env-gated** (`TEST_DATABASE_URL`, `TEST_REDIS_URL`) | Docker unavailable in this WSL distro (see PROGRESS); unit tests never require live services. |
| 11 | `Effective FX rate` scaled integer: `RATE_SCALE = 1_000_000` | Rates like 7.188 CNY/USD = 7_188_000; all integer math, no floats anywhere near money. |
| 12 | Engine for policy: **cedarpy** primary (cp312 manylinux wheel confirmed); a pure-Python deterministic fallback evaluator wraps it for tests without the native lib | Plan §1 allows Cedar or OPA; Cedar has no sidecar requirement. |
| 13 | LLM provider/model/key-pool selection via env (`LLM_PROVIDER`, `LLM_REASONER_MODEL`/`LLM_FAST_MODEL`, comma-separated `<PROVIDER>_API_KEYS`), rendered into the LiteLLM config at startup by `app/harness/litellm_render.py`; one deployment per key so the router round-robins and benches 429/503 keys; secrets stay in env (rendered file holds only `os.environ/` refs) | Matches the research-harness pattern the team asked for; keeps rule 0.8 (proxy-only) and 0.12 (no secrets in files) intact. Default provider remains anthropic. |
| 14 | Local demo deal creation is fixed to the single synthetic tenant `demo-tenant`; request-supplied tenant IDs are ignored | The demo has no authenticated tenant identity provider. Accepting caller-selected tenant IDs would imply isolation that the in-memory runner does not provide. Production tenant auth and persistence remain required. |
| 15 | `verify` upholds findings whose `check_id` is in `CALC_CHECK_IDS` (currently `vat-refund`) once their evidence is grounded in the source PDF; no model adjudicates them | Their numbers come from `calc/`; routing every info finding through the reasoner made a clean deal escalate whenever the model returned no verdict. Ungrounded calc findings still fail closed. |
| 16 | `verify` closes an `lc-consistency` finding that the deterministic battery no longer reproduces *before* the grounding check | After a corrected upload the old evidence quote legitimately disappears from the replaced PDF; requiring grounding there made fixable deals escalate. Findings that still reproduce must still be grounded. |
| 17 | Added `check_latest_shipment` (`lc-late-shipment`, unfixable block) and `check_presentation_period` (UCP Art. 14(c), 21 days); the presentation date comes from a `presentation_schedule` document, merged into the invoice dict by `app/graph/check_inputs.py` (shared by `compliance` and `verify`; invoice values win) | The engine only compared shipment to LC *expiry*, so a shipment after the latest shipment date passed silently. Sharing one input builder stops `verify` from silently closing a finding it cannot reproduce. |
| 18 | Added `import_tax_stack_bdt` (CD, RD, SD, VAT, AIT) to `calc/` | `landed_cost` modelled only CD + AIT; the bill of entry needs the full stack from rule `bd-import-tax-stack`. Rates stay demo assumptions flagged in `seed/rules/`. |
| 19 | Lifecycle corpus lives in `backend/seed/lifecycle/` with its own generator; PDFs paginate and carry a SYNTHETIC banner | The old generator renders one page per document; an LC does not fit. Existing seed PDFs were left byte-identical (manifest proved it). |
| 20 | The one-click approve in the console is a **labelled demo shortcut**: `POST /deals/{id}/sign_demo` has the server sign with the committed demo key (`DEMO_PRIVATE_KEY_B64`). The response carries `demo_shortcut: true` and a notice, the button reads 'Approve with DEMO signer', and a DEMO SIGNER chip sits beside it. It is refused (403) outside `CLEARTRADE_ENV=demo`, and the signature is still verified against the exact rendered deal hash | Lets the demo complete without a passkey device, but it means no human signs in this path, so it must never be presented as a real passkey. Production signers (WebAuthn / WeChat SOTER) keep private keys client-side. To use a real approver instead, set `APPROVAL_PUBLIC_KEYS_JSON` to a non-empty map (the demo key is then not registered). The signed record says so too: `method="demo_key"`, not `webauthn_passkey`. |
| 21 | **Durable deals** (`PERSIST_DEALS=true`, on in compose): deal snapshots (`deal_snapshot`, with the budget counters), the hash-chained audit log (`audit_event`) and the graph checkpoints (LangGraph `AsyncPostgresSaver`) live in Postgres; uploads sit on a volume. The app queries as the non-superuser `cleartrade_app` role with `app.current_tenant` set per transaction, so RLS and the append-only audit grants bind. A restart loses nothing: a deal parked at approval can still be signed and executed (integration-tested, and verified live). Without the flag everything stays in memory, so unit tests need no database | A restart used to drop every deal, every parked approval and the whole audit trail, although the secured tables existed. Known limits: the checkpoint tables are LangGraph's own, owner-connected and not tenant-scoped; SSE queues are in-memory (a restart drops the live stream, not the deal); one process only (the audit chain is serialised with a per-tenant advisory lock, but the in-memory deal cache is not shared). `trade_deal`/`document`/`finding` remain unused by the runner. |
| 22 | Warn-level injection flags (e.g. beneficiary-change language) are **part of the signed approval render** and listed in the approval panel; they do not escalate | They are warnings, not proof of an attack, but a human who can approve past them must see them, and a flag added or removed after signing must invalidate the approval. Found by running each poisoned document alongside a clean live deal. |
| 23 | `DealState.current_extracted`: per document kind, the most recently *uploaded* document's extraction is the one in effect; `merge_doc_refs` keeps upload order. Checks, FX, policy and the approval render all read it | A corrected upload gets a new doc id, so old and corrected extractions coexist; consumers took the first in sha256 order, so the stale invoice won about half the time and the hero correct-and-resume flow failed intermittently. Superseded reads stay in `extracted` for the audit trail. |
| 24 | Extraction drops any snippet that is not verbatim in the parsed document, and the model-facing schema requires `snippet`, `kind` and `fields` | Free models omitted optional fields or paraphrased quotes; one bad snippet sank every finding built from that document at `verify`. `verify` itself stays strict. |
